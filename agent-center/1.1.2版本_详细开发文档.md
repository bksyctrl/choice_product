# 🚀 AgentCenter v1.1.2 详细开发与架构设计文档

## 1. 概述 (Overview)
本文档基于 `1.1.2版本.md` 业务需求说明书编写，旨在指导研发团队完成后端接口、数据库设计、爬虫任务调度、AI 打分算法及前端交互的落地。
**核心业务目标**：围绕**印花工厂基建**与**POD按需定制**，通过跨品类数据抓取与 AI 自动化打分，挖掘具有高迁移价值的爆款视觉设计资产。

---

## 2. 系统架构与技术栈建议
*   **后端服务**：Java (Spring Boot) / Python (FastAPI 数据清洗节点)
*   **数据库**：MySQL (主业务数据) + Redis (缓存/基准值存储)
*   **定时任务**：XXL-JOB / Celery (用于调度爬虫与全量回算机制)
*   **AI 图像处理**：集成内部 ComfyUI / 抠图 API（响应前端“提取插画”指令）
*   **前端**：Vue3 / React + ECharts (用于趋势微型图和分值雷达图)

---

## 4. 核心模块与逻辑实现 (Core Logic)

### 4.1 爬虫与数据同步模块 (Data Crawling Module)
*   **任务触发**：每日凌晨 2:00 触发定时任务。
*   **目标对象**：配置文件中指定的 12 个目标大类下的核心小品类（参考需求文档 2.1 品类下钻地图）。
*   **过滤规则 (硬编码)**：
    *   如果 `sales_30d < 100`，直接丢弃，不入库。
    *   必须解析并存储 `sales_mom` (销售环比) 字段。
*   **后置操作**：数据 Upsert 完毕后，触发 `基准值更新任务`，重算各 `category_id` 的最大销量和最大视频数，存入 Redis 或 基准值表。

### 4.2 AI 综合打分引擎 (AI Scoring Engine)
基于业务提供的公式，在代码中封装为独立的 Service/Util。

**前置风控拦截 (Risk Control)**：
```java
if (rating < 3.0 || price < 1.0 || price > 100.0) return 0.0;
if (sales_30d == 0 && total_sales > 0) return 0.0; // 疑似刷单
```

**分值计算核心代码 (伪代码)**：
```java
// 1. 销量分 (35分)
double norm30d = Math.log10(sales_30d + 1) / Math.log10(max_sales_30d + 1);
double penaltySales = Math.abs(norm30d - 0.5) * 0.67;
double scoreSales = norm30d * (1 - penaltySales) * 2 * 35;

// 2. 评分分 (25分)
double currentRating = (rating > 0) ? rating : 3.5; // 默认值3.5
double scoreRating = (currentRating / 5.0) * 100 * 0.25;

// 3. 热度分 (25分)
double normVideo = Math.log10(video_count + 1) / Math.log10(max_video_count + 1);
double penaltyVideo = Math.abs(normVideo - 0.5) * 0.67;
double scoreVideo = normVideo * (1 - penaltyVideo) * 2 * 25;

// 4. 趋势分 (15分)
double ratio = (sales_7d_normalized) / (sales_30d_normalized); // 需前端或后端做时间窗口归一化处理
double scoreTrend = Math.min(1.0, ratio) * 100 * 0.15;

double finalScore = scoreSales + scoreRating + scoreVideo + scoreTrend;
```

### 4.3 异步全量回算机制 (Async Recalculation)
提供一个管理端 API。当公式权重调整或基准值大幅波动时：
1. 采用线程池（ThreadPoolExecutor）分批读取 `pod_cross_category_product` 表。
2. 调用 `Scoring Engine` 计算新分数。
3. 批量 `UPDATE` 数据库中的 `score` 字段。

## 5. 接口设计 (API Specification)

### 5.1 获取跨品类列表
*   **路径**: `GET /api/v1/products/cross-category`
*   **参数**:
    *   `category_code` (String, 可选, 支持大类或小类)
    *   `score_min` / `score_max` (Double, 可选)
    *   `page` / `size` (分页)
*   **响应 (JSON)**:
    包含基础商品信息、`score`（总分）以及各项子维度的原始值（用于前端渲染图表）。

### 5.2 触发提取插画任务
*   **路径**: `POST /api/v1/products/{id}/extract-illustration`
*   **描述**: 将指定的商品主图发送至 AI 图像处理节点（ComfyUI 抠图流）。
*   **请求体**:
    *   `style_prompt`: (String) 传递需求文档中的“爆款视觉风格”词汇（如 "Acid Graphics, Y2K"），辅助 AI 识别或重绘。
*   **响应**: 返回异步任务 ID 或处理后的图像 URL。

### 5.3 触发全量打分回算
*   **路径**: `POST /api/v1/system/recalculate-scores`
*   **描述**: 管理员手动触发全表分值重算。

## 6. 前端实现说明 (Frontend Implementation)

### 6.1 列表页分值气泡 (Score Bubble)
*   读取 `score` 字段。
*   **CSS 逻辑**:
    *   `score >= 75`: `bg-green-500` (推荐上架)
    *   `50 <= score < 75`: `bg-yellow-400` (观察等待)
    *   `score < 50`: `bg-gray-400` (暂不上架)

### 6.2 趋势微型图 (Sparklines)
*   在“销量走势”列，引入库如 `vue-apexcharts` 或轻量级 `sparkline.js`。
*   后端需返回一个小型数组，如 `[近1周销量, 近2周销量, 近3周销量, 近4周销量]` 用于绘制简易平滑折线。

### 6.3 侧边栏提取预览 (Illustration Drawer)
*   点击列表操作列的【提取插画】。
*   右侧滑出抽屉 (Drawer Component)。
*   展示**原图**与**AI处理后的透明PNG图/分层素材**。
*   提供【一键下载】与【推送到POD素材库】的交互按钮。
